# ACE-Step Forge v0.1.0

![ACE-Step Forge v0.1.0 release header](/images/ace-step-forge-v0.1.0-release-header.png)

This is the first public release of **ACE-Step Forge**. It packages the
official ACE-Step 1.5 engine behind a focused React workspace for creating,
keeping, and sharing local music takes. It also exposes the same generation
queue to coding agents through a local Streamable HTTP MCP gateway.

> Forge is an independently maintained MIT fork. It is not affiliated with
> ACEMusic or the upstream ACE-Step team.

## Highlights

- **Create → Library** — submit text, cover, or repaint jobs from the React
  Router + Vite workspace and retain completed audio in the server-side
  `gradio_outputs/forge-library` catalog.
- **Visualizer videos** — render a completed take as a local H.264/AAC MP4 in
  16:9 landscape or 9:16 social portrait. The video combines the take title,
  generation metadata, an editorial frame, and an audio-reactive waveform.
- **MCP for coding agents** — Claude Code, Codex CLI, and compatible clients can
  call the same local queue through Streamable HTTP. Generated audio lands in
  the same Library as UI-created takes.
- **Bilingual workspace** — switch the Forge UI between English and Japanese;
  the MCP setup page and system status are localized as well.
- **Docker Compose operations** — run the Forge UI, ACE-Step API, and local MCP
  gateway together, with explicit GPU UUID selection through `.env`.
- **Upstream compatibility** — the official Gradio UI remains available through
  the opt-in `legacy` Compose profile.

## Quick start

```powershell
git clone https://github.com/Sunwood-ai-labs/ace-step-forge.git
Set-Location ace-step-forge
Copy-Item .env.example .env
docker compose up -d --build
```

Open `http://localhost:3000`. See the [Forge workspace guide](../FORGE) for
the Library and visualizer workflow, or the [MCP setup guide](../MCP) to
connect Claude Code or Codex.

## Validation

The release candidate was checked with the frontend unit tests and production
build, the visualizer/API route tests, the VitePress documentation build, and
`docker compose config`. A real local Library take was rendered and played in
both the 16:9 and 9:16 visualizer paths.

The complete command inventory is recorded in
[`tmp/release-qa-v0.1.0.md`](https://github.com/Sunwood-ai-labs/ace-step-forge/blob/main/tmp/release-qa-v0.1.0.md).

## Scope and limitations

- This is an initial `0.1` release: APIs, visualizer artwork, and MCP details
  may change in a later minor release.
- The stack is local-first and expects an ACE-Step-compatible NVIDIA setup for
  generation. The visualizer itself renders from completed audio and does not
  use the model GPU.
- The bundled Gradio interface is preserved as a legacy profile; the primary
  Forge experience is the React workspace.
