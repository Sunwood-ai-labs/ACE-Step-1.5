# ACE-Step Forge v0.1.0

![ACE-Step Forge v0.1.0 リリースヘッダー](/images/ace-step-forge-v0.1.0-release-header.png)

**ACE-Step Forge** の初回公開リリースです。公式 ACE-Step 1.5 の生成エンジンを、
生成したテイクを残して使える React ワークスペースとしてまとめました。
同じ生成キューは、ローカルの Streamable HTTP MCP gateway 経由でコーディングエージェントからも利用できます。

> Forge は独立して保守している MIT fork です。ACEMusic や上流 ACE-Step チームとは提携していません。

## ハイライト

- **Create → Library** — React Router + Vite のワークスペースから text / cover / repaint を生成し、
  完成した音声をサーバー側の `gradio_outputs/forge-library` に保存します。
- **ビジュアライザ動画** — 完成した曲を 16:9 横長、または SNS 向け 9:16 縦長のローカル H.264/AAC MP4 に変換します。
  曲名、生成情報、エディトリアルなフレーム、音に同期する波形をひとつの動画にまとめます。
- **コーディングエージェント向け MCP** — Claude Code、Codex CLI などから、Streamable HTTP で同じローカル生成キューを呼び出せます。
  MCP 経由の曲も UI と同じ Library に保存されます。
- **日英のワークスペース** — Forge UI、MCP セットアップ、システム状態を英語 / 日本語で切り替えられます。
- **Docker Compose 運用** — Forge UI、ACE-Step API、ローカル MCP gateway をまとめて起動し、`.env` から GPU UUID を指定できます。
- **上流互換** — 公式 Gradio UI は `legacy` Compose profile から引き続き起動できます。

## 最短起動

```powershell
git clone https://github.com/Sunwood-ai-labs/ace-step-forge.git
Set-Location ace-step-forge
Copy-Item .env.example .env
docker compose up -d --build
```

`http://localhost:3000` を開いてください。[Forge ワークスペースガイド](../FORGE) では
Library とビジュアライザの使い方を、[MCP セットアップ](../MCP) では Claude Code / Codex の接続方法を説明しています。

## 検証

フロントエンドの unit test と production build、ビジュアライザ / API route test、VitePress の docs build、
`docker compose config` を実行しました。実際の Library テイクを 16:9 と 9:16 の両方でレンダリングし、再生まで確認しています。

実行したコマンドは [`tmp/release-qa-v0.1.0.md`](https://github.com/Sunwood-ai-labs/ace-step-forge/blob/main/tmp/release-qa-v0.1.0.md) に記録しています。

## スコープと制限

- 初回の `0.1` リリースです。API、ビジュアライザのアートワーク、MCP の細部は今後の minor release で変わる可能性があります。
- ローカルファーストの構成で、音楽生成には ACE-Step 対応 NVIDIA 環境が必要です。ビジュアライザ自体は完成音声から作るため、モデル用 GPU は使用しません。
- 公式 Gradio UI は legacy profile に残しています。主な利用体験は React workspace です。
